# 09 — Build Roadmap

## Phase 0 — Canonical economics (1 repo, no marketplace)

Ship:

- Business + Agent + Opportunity + Ledger schemas
- deterministic P&L
- badge engine
- scanner score engine
- simulation mode
- basic iOS dashboard

Success criterion: every number and badge can be reproduced from the event log.

## Phase 1 — Shopify operator

Ship:

- Shopify OAuth
- GraphQL Admin adapter
- products/orders/inventory sync
- webhooks + reconciliation
- P&L dashboard
- prompt-to-store planning
- approval-gated product creation/update
- Agent Readiness Score

Success criterion: connect a store and reconcile orders/P&L without manual spreadsheet work.

## Phase 2 — GrailGecko scanner MVP

Ship:

- scanner SDK
- scheduled scan runs
- opportunity inbox
- pay-to-reveal with Bread
- public scanner cards
- immutable version history
- live vs backtest score separation

Success criterion: a creator can publish a scanner and a user can pay to consume standardized output.

## Phase 3 — x402 economy

Ship:

- x402 V2 protected scanner endpoints
- entitlements
- dynamic creator routing
- creator payable ledger
- machine clients
- batch settlement when call volume warrants it

Success criterion: an external agent can discover, pay for, and consume a scanner without a BreadUp UI session.

## Phase 4 — Agent entrepreneur

Ship:

- strategy manifests
- capital policies
- recommend-before-execute
- Shopify mutations
- controlled ad/feed/SEO operations
- job queue and approval inbox
- Jobless badge

Success criterion: a business completes useful recurring operations autonomously within hard policy limits.

## Phase 5 — Scanner/strategy market

Ship:

- fork graph
- creator royalties
- scanner bounties
- leagues
- verified outcome-based reputation
- advanced portfolio analytics

## Phase 6 — Multi-channel / agent commerce

Add channel adapters for marketplaces and agent-commerce protocols based on demand. Keep the Business, Opportunity, Ledger, and Scanner contracts stable.

## Future token gate

A transferable `$BREAD` is explicitly *not* a roadmap dependency. Revisit only after the product has strong non-token utility and specialist legal/app-store review.
